# Website threat model — 20 October 2026

Scope: Astro marketing site, Workers static assets and a prepared but disabled /api/inquiry handler. No live inquiry collection/provider/Turnstile configuration is enabled. Authenticated application, uploads, remote image optimizer and application analytics remain outside the implementation. See docs/V2_PHASE53_PRIVACY_CONTACT.md for activation gates.

| Asset / boundary | Threat and current control | Evidence / remaining owner action |
|---|---|---|
| Repository → trusted Node build → static assets | Dependency compromise, malicious build input or accidental credential publication. Lockfile and pinned direct dependencies; environment/Workers secret files ignored; bounded repository/output scan. | Local build/scan and isolated clean install pass. Astro 7.2.8 / Sharp 0.35.5 / esbuild 0.28.2 close the recorded advisories; full npm audit is zero. Developers/Ops: continue reviewing inputs/dependency updates and keep development on loopback. See docs/V2_SECURITY_ADVISORY_CLOSURE.md. |
| Browser → Cloudflare assets | Injection, framing, MIME confusion, cross-origin requests, stale assets. Tested CSP/security headers; default email handoff has no remote executable resources. Prepared enabled mode permits only the Turnstile script/frame origins; immutable caching remains limited to fingerprinted assets. | Local Workers/browser checks pass. Ops: repeat on the released version, including edge redirects and errors; confirm TLS/HSTS. |
| Browser → visitor email app → approved role mailbox | Header/recipient injection or misleading delivery status. Fixed recipient, encoded body, validated selections; explicit review/send handoff with direct email fallback. No form values in application storage. | Synthetic browser checks pass; no message sent. Ops: mailbox processing/retention and privacy approval remain B3/B13. |
| Gated browser → inquiry Worker → Turnstile / global Durable Object → native email binding → mailbox | Disabled before body consumption. Server enforces method/origin/Fetch Metadata, streamed size/time limits, schema/header safety, honeypot and Siteverify hostname/action/freshness. Transactional keyed counters and reservations limit requests/outbound attempts and duplicate sends; provider messageId is required for accepted status. All API responses no-store/noindex; no raw errors/body logging. | Local unit, actual Workers, native local simulator and mock-enabled browser checks cover success/failure. B3/B13/B14 still block activation: actual sender/inbox/provider, privacy and account configuration, challenge UX/delivery/bounces/rollback. HMAC digests are pseudonymous; active expiry is not total erasure of provider logs/backups/PITR. No real data collected or email sent. |
| Preview host → visitors/crawlers | Unapproved content disclosure. workers.dev noindex tested; noindex is not authentication. | Ops: verify Cloudflare Access and custom/version/alias host coverage; B14 remains open. |
| GitHub / Cloudflare administration | Unauthorized changes or deployment, credential theft. No account-control access during this audit. | Owner/Ops: verify MFA, scoped tokens, protected branches, CI isolation, release identity and known-good rollback. |

Recovery ownership is assigned to the project owner/Ops; approval of named responders remains internal.

| Incident | Detection / containment / recovery |
|---|---|
| Credential exposure | On scanner or provider alert, revoke/rotate first; restrict affected access and preserve sanitized evidence. Identify affected builds/history and access before cleanup. Verify replacement scopes and rebuilt output; owner coordinates required notifications. |
| Defacement / unauthorized deployment | Preserve deployment ID, timestamps and logs; restrict compromised account/token. Restore an authorized known-good artifact only after checking it does not restore exposed credentials/vulnerabilities. Verify content, headers, redirects and release identity. |
| Inquiry abuse or delivery failure | Set CONTACT_DELIVERY_ENABLED=false to reject new submissions and rebuild frontend in email-handoff mode when authorized; this does not recall in-flight/accepted messages. Keep email/phone fallback. Inspect metadata and provider/bounce status without copying inquiry bodies into logs. Reconcile pending/uncertain sends before retry or HMAC rotation; restore only after controls, privacy, provider and production checks pass. |
| Certificate / domain / account compromise | Verify from independent HTTPS/DNS observations and account alerts. Owner/Ops secures administrative access and coordinates provider recovery; do not change DNS blindly. Verify intended hosts, certificate chain, redirects and mail impact. |

This document provides local controls and an operational outline, not a penetration-test certificate or assurance about the MSP's wider operations.
