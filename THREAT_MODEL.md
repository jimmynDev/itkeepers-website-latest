# Website threat model — inquiry-flow update, 27 October 2026

Scope: Astro marketing site, Workers/static assets, active direct browser-to-Formspree forms and separate disabled first-party API preparation. Authenticated application, uploads, remote image optimizer and application analytics remain outside the implementation. Provider/account observations remain owner-controlled; see docs/FORM_INQUIRY_RUNBOOK.md for the operational boundary and evidence checklist.

| Asset / boundary | Threat and current control | Evidence / remaining owner action |
|---|---|---|
| Repository → trusted Node build → static assets | Dependency compromise, malicious build input or accidental credential publication. Lockfile and pinned direct dependencies; environment/Workers secret files ignored; bounded repository/output scan. | Local build/scan and isolated clean install pass. Astro 7.2.8 / Sharp 0.35.5 / esbuild 0.28.2 close the recorded advisories; full npm audit is zero. Developers/Ops: continue reviewing inputs/dependency updates and keep development on loopback. See docs/V2_SECURITY_ADVISORY_CLOSURE.md. |
| Browser → Cloudflare assets | Injection, framing, MIME confusion, stale assets and form-policy mismatch. CSP restricts executable resources; direct provider connections/forms are explicitly allowed. Proposed shared Worker referrer policy matches the static strict-origin-when-cross-origin policy; same-origin URLs retain full detail, cross-origin HTTPS sends origin only, downgrade sends none. Fingerprinted asset cache limits are retained. | Earlier runtime checks are historical. New response-policy regressions are prepared but unrun: required OS sandbox unavailable. Repeat actual released response/CSP checks only after separate release authorization. |
| Browser → Formspree → provider archive / delivery integration → temporary administrator-managed inbox | Untrusted submissions, spam/quota consumption, unintended copies and misleading acceptance. Fixed public endpoint; AJAX payload allowlist, honeypot, credentials omitted, redirects rejected, timeout and conservative retry UI. Native no-JS/verification POST uses the same endpoint. Errors use textContent. Provider acceptance is separate from inbox delivery/scheduling. | Client controls do not enforce the public endpoint's server boundary. Owner must verify activation, exact domain rule, spam/challenge/limits, recipient/workflow copies, archive access/retention and actual RC-origin delivery. Source Worker no-referrer formerly suppressed domain-filter evidence; proposed strict-origin-when-cross-origin restores origin compatibility, not proof of delivery. First-party CONTACT flags do not govern this path. |
| Visitor → approved email/telephone fallback | Independent contact route when the provider is unavailable. Normal website forms do not use mailto handoff. No inquiry values are persisted by the contact controller. | Mailbox receipt, call reachability and operator response are not established by protocol links. Provider outages must not remove these fallback contacts. |
| Retained disabled first-party/native-email preparation | Disabled before body consumption. Source contains method/origin/Fetch Metadata, streamed size/time limits, schema/header safety, honeypot and Siteverify hostname/action/freshness checks, transactional keyed counters/reservations, no-store replies and safe error codes. This is neither active Formspree protection nor the selected future Graph adapter. | Historical fixtures cover this preparation, not current execution or Graph behavior. Revalidate before any reuse; actual sender/recipient, provider contract, privacy, token/guard configuration and recovery remain activation prerequisites. HMAC expiry does not establish erasure of provider logs/backups. |
| Public competition preview → visitors/crawlers | RC/staging are intentionally public under the recorded competition scope; exact-host guards and environment-specific noindex/indexing policies are source-visible. Noindex is not authentication. | Current hosted controls were not freshly observed. Authentication is required if a future preview is intended to be private; do not treat the approved public scope as a newly missing authentication control. |
| GitHub / Cloudflare administration | Unauthorized changes or deployment, credential theft. No account-control access during this audit. | Owner/Ops: verify MFA, scoped tokens, protected branches, CI isolation, release identity and known-good rollback. |

Recovery ownership is assigned to project owner/Ops; Agent03 coordinates inquiry incidents with the Formspree/inbox owner and Workflow. Approval of named responders remains internal. Current direct-flow runbook: docs/FORM_INQUIRY_RUNBOOK.md. Formspree is temporary; future Website → Worker → Graph → Exchange Online processing and Entra application authentication are documented only in docs/M365_CONTACT_MIGRATION_TASK.md. No Graph backend is implemented, and the retained disabled first-party controls do not apply to Formspree.

| Incident | Detection / containment / recovery |
|---|---|
| Credential exposure | On scanner or provider alert, revoke/rotate first; restrict affected access and preserve sanitized evidence. Identify affected builds/history and access before cleanup. Verify replacement scopes and rebuilt output; owner coordinates required notifications. |
| Defacement / unauthorized deployment | Preserve deployment ID, timestamps and logs; restrict compromised account/token. Restore an authorized known-good artifact only after checking it does not restore exposed credentials/vulnerabilities. Verify content, headers, redirects and release identity. |
| Direct Formspree abuse, outage or delivery uncertainty | Follow docs/FORM_INQUIRY_RUNBOOK.md: identify the affected host/form, preserve sanitized time/outcome/provider references, review provider spam/queue/notification/quota evidence and inbox quarantine with its owner. Changing CONTACT flags, disabling notifications or rolling back/removing frontend forms alone does not stop direct provider collection or recall copies. With separate authorization, use a verified provider-enforced stop/restriction and coordinate any frontend fallback release. Do not weaken domain/challenge controls merely to clear a failure or blindly resend timed-out inquiries. Reconcile provider/archive/mailbox copies and confirm authorized recovery checks before restoration. |
| Future first-party activation incident | If that path is separately enabled, its own flags/guard/Turnstile/delivery state require containment and reconciliation. Those actions do not contain the independent Formspree path. No activation or provider setting change is part of this proposal. |
| Certificate / domain / account compromise | Verify from independent HTTPS/DNS observations and account alerts. Owner/Ops secures administrative access and coordinates provider recovery; do not change DNS blindly. Verify intended hosts, certificate chain, redirects and mail impact. |

This document provides local controls and an operational outline, not a penetration-test certificate or assurance about the MSP's wider operations.
