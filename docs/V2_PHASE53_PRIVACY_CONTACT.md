## Implemented controls

- Worker only takes precedence at `/api/inquiry`; existing HTML, redirects, asset caching/headers and unknown-path handling remain asset-first. `CONTACT_DELIVERY_ENABLED=false` rejects before reading a body, calling verification/storage or sending. Missing binding/secret/sender config also fails closed.
- POST multipart only; exact Origin plus request-origin/Fetch Metadata checks. No CORS grants or cookie authentication. Enforced **16 KiB streamed byte cap**, **5s body/verification limits**, field lengths/types, email/header controls, allowed/unique interests, required fields, unknown/duplicate/file rejection and hidden honeypot. Unicode names/messages remain supported; content goes into plain-text email, never HTML or arbitrary headers/recipient URLs.
- Turnstile server validation requires success, exact hostname/action `inquiry`, and a fresh challenge timestamp. Missing/expired/replayed/invalid tokens cannot authorize a new send. Verifier failures reject safely. The raw IP is not forwarded in Siteverify requests.
- One transactional Durable Object coordinates proposed limits: **5 attempts/client per 10 minutes**, **100 requests globally/hour**, **100 outbound reservations/24 hours**. Keys are HMAC-derived from the platform IP; arbitrary forwarded-IP headers are ignored. Shared-network false positives and global-cap denial remain operational review items; these are abuse defaults, not service promises.
- UUID request IDs plus keyed body digests provide bounded duplicate protection across concurrent retries/restarts/IP changes. Pending/uncertain sends cannot be blindly resent; accepted duplicates return acceptance without another provider call. Provider failure/8s timeout or missing messageId never produces success. No automatic resend, queue, autoresponder or marketing enrollment.
- API responses are no-store/noindex with explicit security headers and generic codes, never raw provider errors. No application body/token/raw-IP logging. The store contains only keyed digests/counters/status/expiry/tickets, not inquiries. Active cleanup windows are **10m/1h/24h** depending on record; these are proposed technical defaults, **not approved retention or total-deletion claims**. [SQLite recovery history](https://developers.cloudflare.com/durable-objects/best-practices/access-durable-objects-storage/), provider logs/backups and mailbox retention require separate review.
- Enabled UI uses compact Turnstile, accessible verification/error status and preserved input/retry context, email/telephone fallback, and disabled native API submission without JS. Success says **“Accepted for sending”**, explicitly distinguishing inbox delivery. Default UI loads no Turnstile script and retains its approved wording.
- Conditional build hook adds only Cloudflare's documented script/frame origins when backend forms are actually emitted. Default `public/_headers` and generated CSP are unchanged. No unsafe-eval or extra analytics origins. Local Report-Only browser fixture preceded enforced-CSP checks.
