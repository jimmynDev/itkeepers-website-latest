# Phase 5.3: gated Workers inquiry delivery

Status: prepared locally, disabled, 20 October 2026. User explicitly requested server-side delivery, Turnstile and abuse protection while forbidding real activation or deployment.

Decision: retain Astro SSG and existing Workers static assets. Add `worker/index.ts` only for `/api/inquiry`; all existing routes remain asset-first and unknown routes delegate to ASSETS. Native Cloudflare Email Service outbound `send_email` builder is the first candidate, distinct from Email Routing. No inbound routing, MX/M365, SPF/DKIM/DMARC/account changes or real email binding were made. A provider binding returning `messageId` is required before acceptance is acknowledged; older routing-only void-return bindings cannot satisfy the contract.

Abuse and idempotency require shared state across requests and restarts. A single named SQLite-backed Durable Object coordinates per-client/global attempts, outbound reservations and 24-hour duplicate records using transactions; process-local counters and per-colo rate-limit approximations cannot provide this global cap. No queue, CRM, mailbox storage or new package is added. Only keyed digests/status/counters/expiries persist; legal review must cover these identifiers, cleanup and Cloudflare recovery/backups. Availability tradeoff: coordinator/verification failure rejects safely. Shared networks can hit the proposed five-attempt/ten-minute limit; email/telephone remain available. Limits are proposed technical defaults, not service promises.

The frontend additionally requires PUBLIC_CONTACT_FORM_ENABLED=true, the exact endpoint and a Turnstile sitekey. Its build hook adds only the two documented Turnstile CSP origins to the generated headers in that enabled build; the default policy is byte-identical. No Turnstile script loads in the default email-handoff build. Tokens and secrets never enter metadata or inquiry URLs; Turnstile tokens are transient request data. Uncertain provider acceptance keeps the request reserved to prevent blind duplicate sends. New submissions remain rate limited; idempotency is bounded, not an exactly-once email guarantee.

Consequences: server endpoint, DO namespace/migration and sender/Turnstile secrets require separately approved Cloudflare deployment configuration. Default CONTACT_DELIVERY_ENABLED=false returns 503 without consuming/storing the body or calling external services. Native-provider availability, onboarding, sending-domain DNS changes, mailbox receipt, challenge UX and Privacy legal sign-off remain production gates. Postmark HTTPS Email API is a documented alternative if native sending cannot be approved; it is not activated or silently substituted.
